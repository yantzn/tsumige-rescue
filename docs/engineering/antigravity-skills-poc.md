# TMGR-423 Antigravity Skillsの実行PoC

新規トップレベル会話で、旧Workflowsを使わずに統括・修正・検証を順に実行できるか確認する。使用するのはリポジトリ外の試験用Markdownのみ。Jira、Confluence、GitHubには書き込まない。

## 前提確認

1. リポジトリルートで `git rev-parse HEAD` と `git status --short` を記録する。対象PRの先頭SHAと一致し、作業ツリーがクリーンであることを確認する。
2. 定義を開く前に Available skills で `orchestrator`、`context-management`、`fix`、`fix-verification` が自動登録されていることを確認する。その後、各定義を読み込む。
3. 統括役は指摘ID、対象SHA、修正前の内容、期待結果を記録する。修正担当と検証担当は別コンテキストで起動する。検証担当の書き込みツールを無効にする。

## シナリオ

| ケース | 入力と操作 | 期待結果 |
| --- | --- | --- |
| 正常 | 1行目の「受入確テスト」を「受入確認テスト」に直す。修正前コピー、差分、確認結果を引き継ぐ | 誤字のみ修正。独立した読み取り専用検証が根拠付きで PASS |
| 検証不合格 | 別の一時ファイルで誤字を残した修正候補を渡す。対象SHAと差分は正しく渡す | 検証が根拠付きで FAIL。統括は後続ゲートへ進まず fix に差し戻す |
| 再修正 | 不合格の理由を修正担当に引き継ぎ、正しい修正候補を別コンテキストで再検証する | 根拠付き PASS を受けた後に次の判定へ進める |

各ケースでSkillの適用順、指摘ID、対象SHA、役割のコンテキスト分離、検証担当の書き込みツール設定、検証判定、統括の次工程判定を記録する。判定を推測した場合や別コンテキストが利用できない場合は未検証とする。終了時に作業ツリーを再確認する。

TMGR-406で自動認識と修正検証の正常系を先行確認済み。このPoCで不合格からの差し戻しと再検証を追加確認する。停止上限や権限制御の強制力はTMGR-424で評価する。
